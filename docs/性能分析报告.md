## 2. 计算口径

CoreMark 的 start_time/stop_time 读取 SoC 64 位周期计数器。实际 CPU 时钟由 50 MHz 输入二分频形成，UART 和固件频率常量同时配置为 25 MHz。

```text
运行时间 = 398164697 / 25000000
         = 15.92658788 s

CoreMark = 2000 × 25000000 / 398164697
         = 125.5761758306

CoreMark/MHz = 2000 × 1000000 / 398164697
             = 5.023047033

CoreMark/LUT = 125.5761758306 / 11864
             = 0.01058464058
```

固件串口显示的整数秒为 15；评分采用原始 ticks 计算精确时间。计时超过 10 秒，三个算法 CRC 与对应性能种子期望值一致，且包含完整的 validated 行。

频率降低本身不会提高 CoreMark/MHz。25 MHz 用于满足该双发射实现的布线后时序；每 MHz 成绩来自减少执行周期。

## 3. 编译与体系结构

工具链为 GCC 14.2.0，ILP32 ABI、静态内存。主要编译选项：

```text
-march=rv32i_zba_zbb_zmmul -mabi=ilp32 -mrelax -msmall-data-limit=0
-O3 -flto -finline-limit=1000 -ffreestanding -fno-builtin
```

完整编译选项已随[固件发布](../releases/2026-11-04/coremark/build_flags.txt)保存。CoreMark 核心算法保持原始语义；移植层提供计时、串口输出和裸机运行支持。

| 优化 | 作用 |
|---|---|
| 连续取指与响应缓冲 | 重叠取指和执行，减少前端空拍 |
| BTB 与方向计数器 | 降低循环与跳转重定向开销 |
| 硬件 Zmmul | 替代移位相加软件乘法，两拍完成 |
| Zba/Zbb | 用标准扩展减少部分地址与位操作指令 |
| 快速数据 RAM | 片上数据异步读取，缩短数据访问等待 |
| 双发射与前递 | 在一个执行周期退休两条可兼容的相邻指令 |
| 第二槽控制指令 | 分支/JAL/JALR 可在第二槽完成，减少串行化 |
| LTO 与内联 | 改善跨函数优化，减少动态指令 |

双发射优先保证顺序语义：第二槽访存、乘法或异常指令串行执行；首槽结果可前递给第二槽，第二写回优先处理同目标寄存器写入。

两套镜像的资源数分别对应完整顶层：性能镜像包含扩展执行单元与双发射通路；应用镜像包含中文字符、LCD、触摸和游戏状态接口。不能用扫雷镜像 LUT 计算性能镜像的 CoreMark/LUT。

## 5. 正确性验证

处理器差分验证使用独立软件指令模型，覆盖正常运算、依赖链、跳转、非法编码、未对齐访问、三种总线延迟及提交错误注入。双发射扩展配置累计 135 次运行、55500 条逐项提交核对，覆盖 66 种指令行为。

板级时钟测试使用厂商全局时钟缓冲仿真模型，核对 ÷1、÷2、÷4 的实际边沿周期、MMIO 频率值、UART 位宽和两级复位释放；故意错误的频率元数据能够被拒绝。

扫雷集成测试执行真实 CPU 固件和 GT9147 行为模型，完成 8 关、1882 条断言、6257589 个仿真周期，覆盖首点安全、插旗、触雷、错旗、重开、地形变化和关卡循环。[测试原始日志](evidence/2026-11-04/mine/simulation_integration.txt)与[顶层启动测试](evidence/2026-11-04/mine/simulation_top_smoke.txt)单独归档。

## 6. ILA 基线分析

[早期基线硬件 ILA](evidence/2026-11-04/historical_ila/)来自早期 RV32I 软件乘法版本，采样深度 512、探针 92 路，包含 149 个有效提交样本和 17 个不同提交 PC。波形揭示移位相加乘法内循环反复执行，为增加标准硬件乘法提供了直接依据。

该波形用于基线瓶颈分析，不表示本次双发射镜像的提交行为。当前镜像的周期统计与功能验证来自对应仿真和板测计数，未采集面向当前镜像的 ILA 波形。
