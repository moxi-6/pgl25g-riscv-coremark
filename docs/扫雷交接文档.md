## 2. 数据通路

```
       ┌──────────── CPU (rv32i_core_3stage) ────────────┐
       │  mine.c: 维护 9×9 游戏状态，每帧写 12 个字        │
       └───────────────┬──────────────────────────────────┘
                       │ 写 0x1000_00A0 .. 0x1000_00CC
                       ▼
              video_mine_o[511:0]   ← rv32i_soc 内部寄存器
                       │
                       ▼
              lcd_mine_display      ← 纯组合逻辑，一个像素一个周期
                       │
                       ▼
              lcd_800x480 → RGB 并口 → 7 寸屏

       GT9147 ── I2C ──▶ i2c_master ──▶ gt9147_touch ──▶ MMIO 0x54/0x58/0x5C
                                                              │
                                              CPU 读 tap latch ┘
```

**关键设计原则**：CPU 永远不写像素。它每个帧只发布 12 个 32 位字（其中 11 个字是 81 格 × 4 bit 的打包格状态，第 12 个字是光标），所有字形、网格、旗子、地雷、光标环都由硬件画。这样即使 CPU 只有 1 MHz 级别的性能也能跑满帧。

## 4. MMIO 映射

### 4.1 触摸（`TOUCH_ENABLE=1` 时有效）

| 地址 | 名称 | 读 | 写 |
|---|---|---|---|
| `0x1000_0054` | TOUCH_X | 原始 X 坐标（0..799） | bit0=1 触发重新初始化 |
| `0x1000_0058` | TOUCH_Y | 原始 Y 坐标（0..479） | — |
| `0x1000_005C` | TOUCH_STAT | 状态字（见下） | **写 0 清除 tap latch** |
| `0x1000_0060` | TOUCH_EVT | 事件计数/错误计数 | bit0=1 触发重新初始化 |

**状态字位域**（`rv32i_soc.sv:335` 附近打包）：

```
{18'b0, tp_seq[4:0], tp_count[3:0], tp_status[2:0], tp_tap, tp_pressed}
  bit0        pressed
  bit1        tap_latch    ← 固件靠它判断「点了一下」
  bit[4:3]    status       0=INIT 1=READY 2=NOID 3=IOERR
  bit[8:5]    count        触摸点数
  bit[13:9]   seq          坐标序号（每次更新 +1）
```

> ⚠️ **一定要写一次 `TP_STAT = 0` 才能收到下一次 tap**。`mine.c` 在处理完 tap 后立即清零（第 367 行）。

### 4.2 扫雷格状态

| 地址范围 | 内容 |
|---|---|
| `0x1000_00A0 .. 0x1000_00C8` | 11 个字 = 81 格 × 4 bit，顺序 `k = row*9 + col`，cell k 占 bit `[k*4 +: 4]` |
| `0x1000_00CC` | 光标字：bit[3:0]=col, bit[7:4]=row, bit8=show_all, bit9=won |
| `0x1000_00D0 .. 0x1000_00DC` | 保留未用 |

硬件侧：`mine_selected` 命中 `dmem_addr ∈ [0xA0, 0xE0)`，`mine_idx = (dmem_addr[7:0] - 8'hA0) >> 2`，
按 `dmem_wstrb` 逐字节更新 `video_mine_o[mine_idx*32 + byte*8 +: 8]`（`rv32i_soc.sv:308-315`）。

> ⚠️ **两个过时注释**（代码正确，注释错的）：
> - `atk_l50_mine.sv:3` 写的是 `0x1000_0060..0x1000_009C` —— 那是老的触摸地址段，实际是 `0xA0..0xDC`。
> - `mine.c:4` 写 "16 words at 0x1000_00A0" —— 实际只用了 12 个。

### 4.3 其他（扫雷用到的）

| 地址 | 用途 |
|---|---|
| `0x1000_0000` | LED（低 4 位）= 剩余安全格数取反 |
| `0x1000_0004` | UART：bit31=busy，写低 8 位发一个字节 |
| `0x1000_0008` | KEY[3:0]，**低有效** |
| `0x1000_0044` | **FRAME**：视频帧计数，固件的主循环节拍 |

## 5. 渲染器规格（`lcd_mine_display.sv`）

### 5.1 几何

- 屏幕 800×480，左侧 **640×480** 是游戏区，右侧 160 px 是状态栏（当前只画底色 `0x16202e`）。
- 棋盘：9×9 格，每格 **48 px**，整体 432×432，左上角 **(104, 24)**，右下角 `(536, 456)`。
- 每格内部：外圈 2 px 画网格线（`fx<2 || fx>45`），内部是格面。
- 数字窗口：48×48 格内 **10×14 px**，位于 `(19,17)`，字模按 5×7 放大 2 倍。

### 5.2 tile 编码（固件与硬件必须一致）

| 值 | 含义 | 画面 |
|---|---|---|
| 0 | 未翻开 | 蓝灰 `0x3a4658`，左上角高光 |
| 1..8 | 已翻开，周围雷数 | 深底 + 彩色数字 |
| 9 | 已翻开，空白 | 深底，无数字 |
| 10 | 插旗 | 红旗 |
| 11 | 雷（胜利/失败时揭开） | 黑圆盘 radius 9 |
| 12 | 踩中那颗雷 | 红色背景 `0x8f1f1a` |
| 13 | 错插的旗 | 浅红 `0xff8a80` |

数字配色：1 蓝 `0x4fa8ff`、2 绿 `0x39d353`、3 红 `0xff6b6b`、4 紫 `0xb07cff`、
5 橙 `0xffa33e`、6 青 `0x36d6c3`、7 白 `0xe8ecf4`。

光标环：金色 `0xffd24a`，画在最后（覆盖所有状态）；胜利或 `show_all` 时变绿 `0x39d353`。

### 5.3 除法技巧

不用 `/48`，用魔数乘法：

```systemverilog
wire [21:0] mx = bx * 12'd2731;   // bx/48 ≈ (bx*2731)>>17
wire [4:0]  col = mx[21:17];
wire [9:0]  col48 = {1'b0, col[3:0], 5'b0} + {2'b0, col[3:0], 4'b0};  // col*48
```

## 6. 固件逻辑（`software/mine.c`）

### 6.1 状态

```c
static uint8_t mine[81], open_cell[81], flag[81], adj[81], pushed[81];
static int cur_r, cur_c, level, mine_total, opened_count, flag_count;
static int placed, game_over, game_won, boom_at;
```

### 6.2 关卡

`level_setup(lv)`：雷数 `8 + 2*lv`，即第 1..5 关 = **10 / 12 / 14 / 16 / 18** 颗雷，上限保护 `NCELLS-12 = 69`。

### 6.3 首点安全

`place_mines(safe)` 在玩家第一次点击时才布雷，并且**排除以 safe 为中心的 3×3 区域**，
保证第一下一定翻出空白区而不是靠运气。随机数用 xorshift32（种子 `0x2545F491`）：

```c
rng_state ^= rng_state << 13;
rng_state ^= rng_state >> 17;
rng_state ^= rng_state << 5;
```

### 6.4 翻开与洪水填充

`open_flood(start)` 用显式栈（`int stack[81]`，不用递归，RV32I 栈空间友好）：
打开格子 → 若 `adj==0` 则把 8 邻居入栈。`pushed[]` 防重复入栈。

### 6.5 主循环节拍

```c
for (;;) {
    uint32_t now = FRAME;
    if (now == last_frame) continue;   // 等下一帧
    last_frame = now;
    ... 处理按键 / 触摸 / 过关 / 重开 ...
    render();
}
```

**注意**：主循环完全由 `0x1000_0044` 帧计数驱动，所以 `atk_l50_mine.sv` 里必须保持 `.VIDEO_ENABLE(1)`，
否则 FRAME 不增长，固件会死等在第一帧。（虽然扫雷不画 sprite，但帧同步依赖这条通路。）

### 6.6 输入

| 输入 | 条件 | 动作 |
|---|---|---|
| KEY0 | 上升沿（按下） | `cur_c--`，到头回绕到 8 |
| KEY1 | 上升沿 | `cur_c++`，到头回绕到 0 |
| KEY2 | 上升沿 | `cur_r++`，到底回绕到 0 |
| KEY3 | **松开时**判断 | 按住 <18 帧 → `do_open()`；≥18 帧 → `do_flag()` |
| 触摸 tap | `TP_STAT & 0x2` | 换算格子 → 光标跳过去 → `count<=1` 时直接 `do_open()` |

触摸换算（`touch_to_cell`）：

```c
if (tx < 104 || tx >= 536) return -1;
if (ty < 24  || ty >= 456) return -1;
c = (tx - 104) / 48;
r = (ty - 24) / 48;
```

### 6.7 结束与重开

- 踩雷：`game_over=1`、`boom_at=k`，之后每 `now % 128 == 0` 帧重开本关。
- 过关：`opened_count == 81 - mine_total` → `game_won=1`，`now % 64 == 0` 时进下一关；
  第 5 关过了回到第 1 关。
- `wait_release` 标志防止重开瞬间按键/触摸被误判。

### 6.8 串口输出

`=== FPGA minesweeper ===`、`== level N mines M`、`mines placed`、`open r,c`、
`flag r,c`、`unflag r,c`、`boom`、`level clear!`、`all levels cleared, restart`。

上板调试时直接连串口看这些行就能判断游戏逻辑是否在跑。

## 7. 触摸链路

### 7.1 I2C 地址选择

GT9147/GT911 的 7 位地址由复位瞬间的 INT 电平决定：

| INT 电平 | 地址 |
|---|---|
| 高 | `0x14` |
| 低 | `0x5D` |

驱动默认先试 `0x14`（`ADDR_A`），收不到 ACK 就自动切 `0x5D`（`ADDR_B`）重来一遍
（`gt9147_touch.sv:245-247`）。这同时兼容 GT911 面板。

### 7.2 上电时序

1. `tp_rst_o` 拉低保持 10 ms
2. 按 `addr_sel` 驱动 `tp_int_o`（0x14 需要 INT 高）
3. 释放复位，等 50 ms
4. 读 `0x8140` 起 4 字节产品 ID，校验是否为 `"9147"` 或 `"911"`
5. 写配置寄存器（`0x8040` 等）
6. 进入 10 ms 周期轮询：读 `0x814E`，若 buffer ready（bit7）则读 `0x8150` 起坐标，再写 `0x814E=0`

### 7.3 关键参数

```systemverilog
parameter integer CLK_HZ = 50_000_000;
parameter integer SCL_HZ = 100_000;     // 上板默认 100 kHz
localparam integer MS = CLK_HZ / 1000;
localparam [23:0] POLL_MS = 24'd10;     // 10 ms 轮询
```

`rv32i_soc.sv` 里的 `TOUCH_SCL_HZ` 默认也是 `100_000`。

### 7.4 坐标

GT9147 上报的是**面板原始坐标**（0..799 / 0..479），驱动直接透传到 MMIO，没有做旋转/镜像。
如果上板后发现方向和屏幕不一致，有两个改法：

- 改 `gt9147_touch.sv` 的坐标赋值（加 `799-x` / `479-y`）；
- 或改 `mine.c` 的 `touch_to_cell()` 换算。

**先上板看现象再决定，不要瞎猜。**

## 10. 上板还差的三步

### 第 1 步：写 `sim/tb_mine.sv`

这是**唯一还没写的代码**。建议写法：

```systemverilog
atk_l50_mine #(
    .CLK_HZ(2_000_000),         // 降到 2 MHz，ms 级延时按比例缩短
    .LCD_RESET_CYCLES(2000),    // 默认 500_000 太长
    .TOUCH_ENABLE(1)
) dut (...);

gt9147_model u_model (
    .scl_i   (dut.tp_scl),
    .sda_oe_o(m_sda_oe),
    .sda_o_o (m_sda_o),
    .sda_i   (tp_sda),
    .rst_n_i (rst_n)
);
```

**总线必须显式开漏合并，不能用 `tri1`**（iverilog 下 `tri1` + `assign ... : 1'bz` 会解出 X）：

```systemverilog
wire sda_level = ((dut.tp_sda_oe && !dut.tp_sda_o) ||
                  (m_sda_oe && !m_sda_o)) ? 1'b0 : 1'b1;
assign tp_sda = sda_level;
```

检查点：

1. `dut.u_soc.halted` 和 `trap` 全程为 0（否则 LED 全亮、游戏不跑）；
2. `dut.tick` 周期性地脉冲（帧在跑）；
3. `dut.mine_state` 复位后全 0（81 格全盖 + 光标在左上）；
4. `u_model.inject_touch(200, 120)` → 等 3 帧 → `mine_state[83:80] != 0`
   （tx=200,ty=120 → col=2,row=2 → k=20 → bit 80..83）；
5. `key=4'b0111` 保持 1 帧再松开 → 当前光标格被翻开；
6. `lcd_rgb` 不出现 `x`。

> 一帧 = 1056×525 ≈ 554k 周期。2 MHz 下跑 10 帧约 5.5M 周期，iverilog 几分钟能出结果。
> 帧计数依赖 `VIDEO_ENABLE=1`，顶层已经给对了。

## 11. 上板后必须验证的三件事

1. **触摸坐标方向**。GT9147 原始值与 LCD 像素是否一一对应？面板可能旋转或镜像。
   现象：点左上角，光标跑到右上角 → X 镜像；点上方光标跑到下方 → Y 镜像。
2. **I2C 地址**。读不到 ID（`status=2 NOID`）时先量 `tp_int`（L5）在复位时的电平。
   另外确认板子上有没有触摸线的上拉电阻，没有的话 SDA/SCL 都拉不高。
3. **SCL 频率**。默认 100 kHz，接线长或有干扰时先降到 50 kHz 排查
   （改 `rv32i_soc.sv` 的 `TOUCH_SCL_HZ`）。

调试抓手：串口打 `=== FPGA minesweeper ===` 说明固件在跑；读 `TP_EVT` 能看到 NACK 计数。

## 12. 踩过的坑（别重复踩）

1. **`0x1000_0044` 是视频 FRAME，不是空闲地址**。触摸最初放在 `0x40..0x4C` 和它撞车，
   固件读帧号会读到触摸 Y，表现为游戏卡在第一帧。现已挪到 `0x54..0x60`。
2. **iverilog 的 `tri1` + `assign ... : 1'bz` 会解析出 X**，I2C 总线必须显式开漏合并。
3. **i2c_master 读路径必须真的把「地址 + R」发出去**，老版本漏了这一步，读回全 `0xFF`。
4. **`dist`、`cell`、`bit` 是 SystemVerilog 关键字**，不能当标识符。
   `lcd_mine_display.sv` 里已经改名 `radius2`。
5. **`-Werror` 会拦下未使用变量**（`force_render` 那次），删干净就行。
6. **需要 `coremark/softmath.c`**，否则链接报 `__divsi3/__modsi3/__udivsi3/__umodsi3` 未定义。
7. **`TOUCH_ENABLE` 默认是 0**（`rv32i_soc.sv:17`），顶层必须显式传 1，否则触摸模块根本不例化。
