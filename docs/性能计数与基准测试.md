# 性能计数与基准测试

2026-10-22：基础 CPU 已经实板通过 UART/GPIO/两次物理复位；本次新增软件可读性能计数器，为 CoreMark 计时和 CPI 分析提供基础。

## 只读 MMIO

| 地址 | 读值 |
|---|---|
| `0x10000010` | 运行周期计数低 32 位 |
| `0x10000014` | 运行周期计数高 32 位 |
| `0x10000018` | 已提交指令计数低 32 位 |
| `0x1000001c` | 已提交指令计数高 32 位 |
| `0x10000020` | SoC 配置的 `CLOCK_HZ`，板级默认 50,000,000 |

两个计数器均为 64 位，复位清零，溢出按模 2^64 回卷。周期计数在复位释放后每个时钟加一，包含取指、访存、串口等待，以及 CPU 停机后的时钟；提交计数仅在核心现有 commit 事件上加一。当前核心不提交 EBREAK 和故障指令，因而不计这两类指令。跳转错误路径、等待周期与空泡不能增加提交数；停机后提交数保持。

这些是本 SoC 的 MMIO 计数寄存器，不是 RISC-V CSR。全部只读，软件写入被忽略。支持现有 CPU 的字节/半字读语义；区域外仍按现有未映射地址返回零，不新引入总线异常。

`CLOCK_HZ` 是配置值，不是测量频率。当前时钟来自标称 50 MHz 板载时钟，未独立测量实际频率。

## 软件接口

使用 `software/perf.h` 的 `perf_cycles()`、`perf_instret()`、`perf_clock_hz()`。64 位读采用“高→低→高，若高位变化则重读”，避免 32 位总线读取低位回卷时拼出错误值。两个不同计数器没有联合快照；读本身也消耗周期和指令，短工作负载不能直接当作纯算法 CPI。

计时区间的秒数可由 `cycle_delta / CLOCK_HZ` 求得。正式测评须保留完整 64 位差值，不能用会在 50 MHz 下约 85.9 秒回卷的低 32 位代替。CoreMark 至少运行 10 秒，需使用正式 CoreMark v1.0、正确种子/CRC、自定义移植层和迭代次数；本次 `perf_test.c` 只是读数与 C 集成验证，不是 CoreMark，也不产生参赛分数。

## 可复现验证

在项目根目录运行：

```powershell
& .\fpga_riscv_starter\scripts\run_iverilog.ps1 -RebuildFirmware
```

完整回归现为 **14 项**（性能计数接入时为 12 项，其后加入 `tb_perf_report` 与 CoreMark 的 `tb_coremark`）：新增 `tb_soc_perf` 与 `tb_perf_firmware`。前者通过真实 CPU 指令检查只读 MMIO、部分字读、区间外读、64 位回卷、等待、错误路径丢弃、停机和复位；仅为加速回卷验证，在首轮复位末尾将计数器置于边界值，第二轮从真实零复位开始。后者用 GCC 从源码编译 `perf_test.c`，执行带 RAM 读写的校验和循环，读取计数器并检查差值，UART 解码 `PERF OK\r\n`，连续两次复位运行。

```powershell
& .\fpga_riscv_starter\scripts\build_firmware.ps1 -App perf_test -Rebuild
```

本轮 PDS 已在独立 `C:/fpga/riscv_l50/perf_stage_20261022/cpu` 完成 PGL25G/-6/MBG324 的综合、布局布线与时序报告。Vcc33、20 ns 时钟下 `All Constraints Met.`，setup +1.868 ns、hold +0.141 ns；工具估算频率 55.1511 MHz，不是实测最高工作频率。综合报告为 1815 LUT、1394 FF、16 DRM18K，相对旧版综合的 1613 LUT/1266 FF 增加 202 LUT/128 FF。时序验证范围是已声明的时钟约束，外部异步复位与 LED/UART 延迟未建立板级预算。
