## 3. MMIO 映射（以 `rtl/soc/rv32i_soc.sv` 当前值为准）

| 地址 | 名称 | 说明 |
|---|---|---|
| `0x1000_0000` | GPIO / LED | 低 4 位 = LED |
| `0x1000_0004` | UART | bit31 = busy |
| `0x1000_0008` | KEY | 低 4 位，**低有效** |
| `0x1000_0010` | CYCLES | 周期计数 |
| `0x1000_0018` | INSTRET | 指令退休数 |
| `0x1000_0020` | CLOCK_HZ | 常量 50 000 000 |
| `0x1000_0030` | HUD | video 通道（扫雷未用） |
| `0x1000_0044` | **FRAME** | ⚠️ video 通道的帧计数，扫雷固件靠它做帧同步 |
| `0x1000_0050` | COMMIT | video pending |
| `0x1000_0054` | **TOUCH_X** | 触摸 X（0..799） |
| `0x1000_0058` | **TOUCH_Y** | 触摸 Y（0..479） |
| `0x1000_005C` | **TOUCH_STAT** | 状态字，**写 0 清 tap** |
| `0x1000_0060` | TOUCH_EVT | 事件计数/错误计数，写 bit0 = 重新初始化 |
| `0x1000_00A0..0x00DC` | **MINE tiles** | 16 个 32 位字，9×9 格 4 bit 打包 + cursor |
| `0x1000_0100..0x017C` | video sprites | 射击游戏用 |

### 3.1 触摸状态字编码（`0x1000_005C`）

```
{18'b0, tp_seq[4:0], tp_count[3:0], tp_status[2:0], tp_tap, tp_pressed}
 bit0      pressed
 bit1      tap_latch   ← 固件靠它判断「点了一下」
 bit[4:3]  status      (0=INIT 1=READY 2=NOID 3=IOERR)
 bit[8:5]  count       触摸点数
 bit[13:9] seq          坐标序号
```

⚠️ **固件每处理完一次 tap 必须写一次 `TP_STAT = 0`**，否则下一次 tap 不会置位。

### 3.2 扫雷 tile 编码（`lcd_mine_display.sv` 约定，固件必须一致）

| 值 | 含义 |
|---|---|
| 0 | 未翻开（蓝色盖） |
| 1..8 | 已翻开，周围雷数 |
| 9 | 已翻开，空白 |
| 10 | 插旗 |
| 11 | 显示为雷（胜利时揭开） |
| 12 | 踩中的那一下（爆炸色） |
| 13 | 错插的旗（浅红） |

打包方式：**4 bit / 格，按 `k = row*9 + col` 顺序**，81 格 = 11 个字（`TILES[0..10]`），
第 12 个字 `TILES[11]` 是光标字：

```
bit[3:0]  cur_col
bit[7:4]  cur_row
bit8      show_all
bit9      won
```

## 4. 扫雷玩法与操作（`software/mine.c` 已实现）

- 9×9 网格，**5 关**，第 n 关雷数 = `8 + 2*n`（10/12/14/16/18）。
- 首次点击时有 **3×3 安全区**，保证开局不是靠运气。
- 翻开空白格走 BFS 洪水填充；旗子数量上限 = 雷数；全部非雷格翻开即过关。
- 踩雷 → 显示爆炸后 2 秒重开本关；过关 → 短暂停顿后进下一关。

操作：

| 输入 | 动作 |
|---|---|
| `KEY0` / `KEY1` | 光标左 / 右 |
| `KEY2` | 光标下移（到底回绕） |
| `KEY3` 短按（<18 帧） | 翻开当前格 |
| `KEY3` 长按（≥18 帧） | 插旗 / 取消旗 |
| 触摸单击 | 光标跳到该格**并直接翻开** |
| UART | 打印 `=== FPGA minesweeper ===` 及各事件 |

LED 显示「剩余安全格数」取反。

**总线接法必须显式计算，不要用 `tri1`**：

```systemverilog
wire sda_level = ((dut.tp_sda_oe && !dut.tp_sda_o) || (m_sda_oe && !m_sda_o)) ? 1'b0 : 1'b1;
assign tp_sda = sda_level;     // 顶层内部也是 ?0:z，两边值恒等，不会冲突
```

检查点：

1. `dut.u_soc.halted` / `trap` 始终为 0；
2. 帧计数持续增长（`dut.tick`）；
3. `dut.mine_state` 复位后全 0（全盖）；
4. `u_model.inject_touch(200, 120)` → 等 3 帧 → `due.mine_state[83:80] != 0`

5. `key=4'b0111` 保持 1 帧再松 → 当前光标格被翻开；
6. `lcd_rgb` 不出 X。

## 7. 踩过的坑（别重复踩）

1. **`0x1000_0044` 被 video FRAME 占用**。触摸最初放在 `0x40..0x4C`，和 FRAME 撞车，
   固件读帧号会读到触摸 Y。现已挪到 `0x54..0x60`。
2. **iverilog 的 `tri1` + `assign ... : 1'bz` 会解析出 X**，I2C 总线必须用显式开漏合并
   （见 `sim/tb_touch.sv` 第 20 行）。
3. **i2c_master 读路径必须真的把「地址 + R」发出去**，老版本漏了这一步，读回全是 0xFF。
4. **`dist` 是 SystemVerilog 关键字**，`lcd_mine_display.sv` 里已改名 `radius2`。
   同理 `cell`、`bit` 也不能当标识符。
5. **`__divsi3/__modsi3/__udivsi3/__umodsi3` 需要 `coremark/softmath.c`**，
   RV32I 无除法指令，`mine` 镜像的 `EXTRA_SRCS` 已加上。
6. **固件编译带 `-Werror`**，未使用的变量会直接失败。
