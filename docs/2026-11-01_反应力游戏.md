# 反应力小游戏（实际应用演示）

> 2026-11-01。赛题要求"一个实际应用场景"，本演示是 RISC-V 软核在 ATK-L50 上的可交互用途：
> CPU 随机点亮 4 颗 LED 之一，玩家在 3 秒内按下对应 KEY，串口打印每轮反应时间与整局成绩。
> 不新增任何外设，只用板载 LED、KEY 与板载 UART。

## 1. 规则

- 一局 `10` 轮（`ROUNDS`）。每轮 CPU 先静默 `0.6–2.0 s`（随机），再点亮 `LED0–LED3` 中的一颗并开始计时。
- 玩家在 `3 s`（`HOLD_TIMEOUT`）内按下与灯号一致的 `KEY0–KEY3`：判 `OK`，反应时间 = 点灯到按键的 `perf cycle` 差 / 50 MHz。
- 按错键：判 `WRONG KEY`，本轮计 0 分并立即熄灭 LED。
- 超时：判 `TIMEOUT`。
- 10 轮结束打印 `Match: <hit>/10 hit, avg <n> ms, best <n> ms`，等待任意键开下一局。

串口 `COM8`，`115200 8N1`。

## 2. 硬件改动（只加了一根只读通路）

| 文件 | 改动 |
|---|---|
| `rtl/soc/rv32i_soc.sv:12` | 新增端口 `input logic [3:0] key_i` |
| `rtl/soc/rv32i_soc.sv:20` | 新增 `localparam logic [31:0] KEY_ADDR = 32'h1000_0008;` |
| `rtl/soc/rv32i_soc.sv:118,146` | `key_selected` 译码；读 `0x1000_0008` 返回 `{28'b0, key_i}` |
| `rtl/top/atk_l50_top.sv:10,19` | 新增 `input logic [3:0] key`，接到 `.key_i(key)` |
| `constraints/atk_l50_vcc33.fdc:71-93` | `key[0]=V12`、`key[1]=T12`、`key[2]=N9`、`key[3]=M10`，`INPUT`、`3.3 V`、`LVCMOS12` |

KEY 为**低有效**（按下接地，外部上拉），因此全松开时寄存器读到 `0xF`。这是本轮唯一新增的输入路径；
GPIO 输出、UART、性能计数器均为既有设计，未改动。

## 3. 软件设计（`software/game.c`）

- `keys_raw()` 直接读 `KEY_ADDR`；`keys_settled()` 做 `5 ms` 去抖（间隔两次一致才采信）。
- `now_cycles()` 读性能计数器 `0x1000_0010/0x1000_0014`；`now_ms()` = 周期差 / 50000（50 MHz）。
- RNG 用 xorshift32，种子取自上一局最后一个按键时刻与周期低位的异或，避免每次开局序列相同。
- 点灯：写 `GPIO_ADDR` 低 4 位；熄灯：写 `0`。

### 关键修复（本轮由仿真复现的两个真 bug）

1. **低有效按键被当成高有效判断**（会导致上板永远判 TIMEOUT）。
   - 旧：`uint32_t pressed = keys_settled(); if (pressed != KEY_MASK && (pressed & (pressed - 1u)) == 0u)`
   - 按键低有效时"只按一个键"的原始值是 `0b1011`，`0b1011 & 0b1010 = 0b1010 ≠ 0`，条件恒假。
   - 新：`uint32_t pressed = (~keys_settled()) & KEY_MASK;` 再判 `pressed != 0 && (pressed & (pressed-1)) == 0`，索引用 `(pressed & (1u<<i)) != 0`。
2. **成绩文本把轮数写死成 10**（仿真只跑 2 轮时匹配失败，也说明上板换 `ROUNDS` 会打印错）。
   - 改为 `uart_putu(ROUNDS)` 动态打印，欢迎语与 `Match:` 行都跟着走。

另外新增 `uart_puthex()` 与开机自检打印 `KEY register reads 0x0000000F ...`，用于一眼确认按键寄存器通路。

### 仿真镜像

板级镜像每轮要等 3 秒真实超时，Icarus 跑不动（3 s ≈ 1.5 亿周期）。`-DGAME_FAST_SIM` 把
`ROUNDS=2`、`HOLD_TIMEOUT=120 ms`、静默窗压到 `5–10 ms`，逻辑路径完全相同。
`scripts/build_firmware.ps1 -App game` 会同时产出板级镜像（无宏）与仿真镜像 `software/build/game_sim/firmware.hex`。

## 4. 验证证据

### 仿真回归（`sim/tb_game.sv`，纳入 `scripts/run_iverilog.ps1` 第 15 项）

```
[PASS] reflex_game captured 351 UART bytes in 1457208 cycles, Match 1/2 (one OK, one WRONG KEY)
```

测试线程在第 1 轮灯亮后 1 ms 按对应键（得到 `R1: LED2 -> OK 4 ms`），第 2 轮故意按错键
（得到 `WRONG KEY`），覆盖了"按键识别 + 极性 + 时间戳 + 计分"整条链路。

### 上板（`build/uart_capture/game_board_20261101_04/`）

```
=== ATK-L50 RISC-V reflex game ===
KEY register reads 0x0000000F at boot (0xF = all keys released, low nibble = KEY0..KEY3 active-low).
One LED lights at a random moment: press the matching KEY fast.
10 rounds per match; press any key to start the next match.

-- new match --
R1: LED2 -> TIMEOUT
...
R10: LED0 -> TIMEOUT
Match: 0/10 hit
Press any key for another match.
```

这一局**无人按键**，所以全 TIMEOUT 属预期；它证明了：程序完整跑完 10 轮、点灯/计时/超时分支正常、
开机读到 `0xF`（按键全部松开，输入通路电平正确）。带按下按键的一局需要现场按 KEY，
用 `scripts/run_game_capture.ps1` 一键复测。

> 注：`game_board_20261101_02/03` 是修复 bug 1 之前采的，按了键也会 TIMEOUT，不能作为交互证据。

## 5. 复现命令

```powershell
# 构建板级固件与位流
scripts/build_firmware.ps1 -App game
scripts/run_pds.ps1 -Target cpu -FirmwareApp game -ConstraintProfile Vcc33 -Stage Bitstream

# 仿真回归（含 tb_game）
scripts/run_iverilog.ps1

# 上板 + 采集（按提示按 KEY）
scripts/run_game_capture.ps1 -Port COM8 -TimeoutSeconds 150
```

发布包：`build/board_release/cpu/game/atk_l50_top.sbit`。

## 6. 边界

- 计时分辨率 1 个 `perf cycle`（20 ns），去抖窗口 5 ms 远大于按键抖动，反应时间误差 < 10 ms。
- 只用低 4 位 LED 与 4 个 KEY；板载其余 LED 保持熄灭。
- 当前板上位流即修复后的 game 镜像（2026-11-01 14:0x 下载）。
