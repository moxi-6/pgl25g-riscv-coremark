# CoreMark 优化接续：R6–R9 与上板验证

用户目标：**CoreMark/MHz 超过 5，达到后继续优化。目标仍 active，尚未由实板证明完成。** 最新安排是先把现有 R9 上板验收，暂停新增性能方案；应用开发继续暂缓。R9 单轮性能仿真为 **5.34542 CoreMark/MHz**，官方 validation 种子也已通过。当前 PDS 正在处理双银行 ROM 的初始化/映射兼容问题，尚无 R9 可下载且时序通过的发布结论，也没有新增上板成绩。

本记录覆盖旧 HANDOFF/README 中“CPU 优化尚未开始”“快速 RAM 尚未综合”“验证种子未跑”等过时描述。当前运行句柄与最新 PDS 路径由主代理收尾时补入；恢复工作先检查对应进程和实际日志，不依据旧 session 重启任务。

## 当前实现

- 基础 CPU 保留 `rv32i_core_3stage.sv` 文件名，连续同步取指、带标签 BTB、WB 前递；`PIPELINE_DECODE` 控制独立译码级，双发射时使用三段路径。
- 标准 Zmmul 支持 `MUL/MULH/MULHSU/MULHU`，除法仍非法。新增 `MUL_CYCLES=2/3`；R9 采用两拍 EX，较三拍每条乘法减少一次等待。数据寄存器保持无复位以利 DSP 推断。
- 标准 Zba 支持 `SH1ADD/SH2ADD/SH3ADD`；Zbb 支持逻辑取反、计零/计数、MIN/MAX、符号/零扩展、旋转、ORC.B、REV8。译码核对精确编码，RV64 或保留编码不可误接受。
- 双发射取相邻两条，四读口/双写口寄存器堆，首槽结果可前递给第二槽。第二槽可执行普通 ALU 与分支/JAL/JALR；访存、乘法及异常指令转首槽串行执行。首槽跳转消除第二槽；第二槽自身预测失败仍退休并刷新后续指令。
- R8 为两个 PC 查询、训练 BTB；R9 板级候选 `BTB_ENTRIES=128`。首条预测跳转时只取一条，第二条预测随请求及缓冲保存，串行时继续使用。
- `FAST_DMEM=1` 使用异步读、同步字节写的分布式 RAM，消除本次 CoreMark 的数据等待。该设计的硬件资源与最高频率必须以对应 PDS 实现为准。
- 指令 ROM 已扩为 **64 KiB / 16384 words**，链接脚本与固件检查器一致。双发射使用偶/奇两个银行；启动代码读取 ROM 数据有独立同步端口。PDS 不接受将 `$readmemh` 临时数组复制给银行的初始化写法，现改为直接读取 `.even/.odd` 文件；`split_imem_banks.py`、profiler、板级准备脚本生成这些文件。硬件映射仍在确认。
- CPU 板级顶层已传递 `ZMMUL_ENABLE/BITMANIP_ENABLE/DUAL_ISSUE/FAST_DMEM/PIPELINE_DECODE/BTB_ENTRIES/MUL_CYCLES`。当前候选扩展与双发射开启，`PIPELINE_DECODE=0`、BTB128、MUL2；旧 SoC/应用默认模式保留。

## 性能证据

以下都是 **ITERATIONS=1、性能种子 CRC 匹配的仿真推算**，不是比赛正式上板成绩。计算为 `1000000 / timed_cycles`；计时区间与固件实际 MMIO 计时 ticks 严格核对。上板仍需至少 10 秒、实际时钟与元数据一致。

| 配置 | 周期 | 退休指令 | 仿真 CoreMark/MHz |
|---|---:|---:|---:|
| R2 RV32I 三段预测 | 993871 | 870108 | 1.00617 |
| R4 Zmmul 四段、O2、同步 RAM | 437456 | 315300 | 2.28594 |
| Zmmul O3/relax/unroll、同步 RAM | 393821 | 278527 | 2.53922 |
| R5 O3/unroll、快速 RAM、三段 | 315987 | 278527 | 3.16469 |
| R6 加 Zba/Zbb、O3/unroll | 307307 | 268233 | 3.25407 |
| R6 Zba/Zbb、O3/LTO/inline1000 | 296413 | 254839 | 3.37367 |
| R7 双发射、第二槽仅 ALU、BTB16 | 244687 | 254839 | 4.08685 |
| R8 第二槽控制指令、双 PC 预测、BTB16 | 208527 | 254839 | 4.79554 |
| R8 BTB64、三拍乘法 | 198519 | 254839 | 5.03730 |
| R8 BTB128、三拍乘法 | 196472 | 254839 | 5.08978 |
| **R9 BTB128、两拍乘法** | **187076** | **254839** | **5.34542** |

R9 精确分解：`187076 = 254839 − 87797 双退休节省 + 10638 重定向空泡 + 9396 乘法等待`。数据等待为 0，重定向 5319 次。R8→R9 的 9396 周期改进恰好对应 9396 条硬件乘法各少等一拍。

性能证据目录为 `build/optimization_20261103/`（历史命名保留）：

- R6：`cpu_r4_o3_unroll_b_20261104`、`cpu_r4_o3_lto_inline_b_20261104`。
- R7：`cpu_r7_dual_20261104`。
- R8：`cpu_r8_dualbranch_20261104`、`cpu_r8_btb64_20261104`、`cpu_r8_btb128_20261104`。
- R9：`cpu_r9_mul2_btb128_20261104`；各目录含 `summary.json`、`run.log`、固件副本和源码 SHA256。

R9 独立 validation 种子结果为 **188163 周期、255219 条退休**，CRC `seed=18f2 / list=e3c1 / matrix=0747 / state=8d84` 全部通过。证据在 `cpu_r9_validation_20261104/`。这组用于正确性检查，不能替代性能种子正式分数。

当前最近确认的正式实板成绩仍是早期重叠取指设计：**23.7844008 CoreMark @50 MHz = 0.47569 CoreMark/MHz**，300 迭代、630665457 ticks；不是 R9。

## 固件与发布约束

CoreMark 上游核心算法保持不变，无特定分数捷径。`start_time/stop_time` 的 `noinline/noclone/externally_visible` 保持 LTO 计时入口；软件运算库入口保留 `used/externally_visible` 以防 LTO 丢失后端生成的引用。

- 当前性能仿真固件：`software/build/coremark_o3_lto_inline_b_sim/`，39840 bytes，`-march=rv32i_zba_zbb_zmmul -O3 -mrelax -flto -finline-limit=1000`，ITERATIONS=1。
- validation 仿真固件：`software/build/coremark_o3_lto_inline_b_validation_sim/`，39864 bytes，另有 `-DVALIDATION_RUN=1`。
- `software/build/coremark/firmware.json` 已记录同 ISA、O3/LTO/inline1000 的板用自动迭代固件，39820 bytes。发布前继续检查 manifest 源哈希；不要复用过期构建。
- `build_firmware.ps1` 与 `prepare_board.ps1` 已接受 `rv32i_zba_zbb_zmmul`，编译参数、build_flags 和发布包检查须与当前顶层能力一致。
- LTO 输出省略 C `STT_FILE` 名称，固件检查用 `main/_start` 加实际源哈希补充来源核对，仍保留 ABI、编码、内存布局检查。
- 编译扫描脚本现合并既有 `compiler/summary.json`，不再只保留最后一次请求的 variants。

## 当前接续顺序

1. 先收尾现有 R9 PDS，确认两银行 ROM 正确映射，查看完整资源与时序报告。`-Stage Timing` 的进程成功不等于时序满足，必须读取 WNS。
2. 在实际约束下生成位流并做板包审计。若需降低实际时钟，应同步时钟生成、UART、CLOCK_HZ 与约束，不可仅改计时元数据。
3. 发现板卡、下载并回读；采集至少 10 秒性能种子的 UART 原始 ticks、iterations、CRC、实际频率，计算 CoreMark/MHz。按板用验证流程继续 validation 验收。
4. 只有实板证据证明超过 5 才能认定阈值达成；随后按用户目标继续优化。眼下先上板，不再启动新性能方向。
