## gouten（STATUSR bit 17）：合法 CLI 命令集内确认无解

实机复核后，CLI 下载链路缺的**只有一个 bit**：

| | STATUSR | bit 17 gouten |
| --- | --- | --- |
| CLI `program_sram.ps1` | `0x001dfca0` | **0** |
| PDS GUI Program | `0x001ffca0` | **1** |

xor = `0x00020000`，DONE(12)/glogen(14)/vddt_n(16)/grsn(18)/gwen(19)/pll_lock(20)
两边完全相同 —— 位流配置是成功的，只是输出未使能，IO 高阻，串口恒 0 字节。

**已穷尽、请勿重复的实验**：

| 尝试 | 结果 |
| --- | --- |
| `cfg_operate_ctl -mode 0..8` | 合法范围仅 `0~2`，语义是 CTL 的 program/read/erase，与 gouten 无关 |
| `cfg_reset_fpga` | 成功，STATUSR→`0x000dfca0`（只丢 bit 16），gouten 仍 0 |
| `cfg_exit_user_mode` | `invalid command name`，不存在 |
| `cfg_help` 全量审查（129 行） | 无任何命令操作 bit 17 |

**注意副作用**：`cfg_reset_fpga` 会让板子进入复位态。若跑过它，必须重新
`program_sram.ps1 -Target cpu -FirmwareApp <app>` 才能恢复。

**结论**：CLI 无法设置 gouten，这是工具未暴露的能力，不是参数问题。
