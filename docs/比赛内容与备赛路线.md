# 2026 FPGA 创新设计赛道：比赛内容与备赛路线

更新日期：2026-09-14

## 1. 比赛是什么

本目录中的官方选题指南显示，比赛为**全国大学生嵌入式芯片与系统设计竞赛 2026 - FPGA 创新设计赛道**，命题企业为深圳市紫光同创电子有限公司。赛道要求使用紫光同创 FPGA 平台，推荐工具为 Pango Design Suite（PDS）。

竞赛总官网将 FPGA 创新设计赛道列为独立赛道，首页标示活动周期为 **6 月至 12 月**。具体报名截止、初赛提交、决赛时间、队伍人数和当年章程应以官网最新通知为准；现有选题指南没有给出这些日期与规则。

## 2. 官方提供的技术平台

选题指南列出以下平台：

| 平台 | 核心器件/结构 | 适合方向 |
|---|---|---|
| RK3568_MES2L100H | Logos2 PG2L100H + RK3568 ARM，DDR3、Flash、HSST、SFP、FMC 等 | 软硬件协同、ADAS、多路视频 |
| 盘古 676 系列 | PG2L100H/PG2L200H，DDR3、HDMI、以太网、PCIe/HSST 等 | CPU、图像、通信、高速接口 |

配套外设包括 OV5640 双目摄像头模块，以及 FMC 转 40Pin/SMA 扩展模块。选板时先看赛题和资源，再看价格；不要只比较 LUT 数量。

## 3. 四个选题方向

### 选题一：基于紫光同创 RISC-V 指令集 CPU 设计

这是与你重做 24ysyx E2 最一致的方向。

基础任务：

- 实现支持 RV32I 基础整数指令集的通用处理单元；
- 设计不少于 3 级的流水线；
- 处理数据冲突和分支跳转；
- 集成 UART、GPIO 等基础外设。

高阶任务：

- 两路组相联指令 Cache 与数据 Cache；
- 动态分支预测，例如 BTB；
- 完整 RISC-V 异常/中断；
- 以自研 CPU 为基础构建边缘 AI 加速系统。

主要评价：CoreMark/MHz、最高工作频率、CoreMark/LUT、应用场景效果、代码规范与性能分析。官方要求 CoreMark 测试运行不低于 10 秒，并要求利用 ILA 波形分析关键算法的流水效率。

### 选题二：基于紫光同创 FPGA 的任意角度畸变矫正

基础任务包括视频采集/缓存/显示、二阶径向或切向畸变映射、双线性插值。高阶任务包括 IMU/上位机控制的动态矫正、流水线加速和自适应 Gamma/直方图均衡。评价重点是标定参数真实性、MTF50/SFR 或直线度、1080P@30/60fps、端到端延迟和资源利用率。

### 选题三：以紫光同创 FPGA 为核心的高级辅助驾驶系统

基础任务包括图像采集显示、MCU 与 FPGA 高速通信、道路场景处理与识别。高阶任务包括至少四路视频并行采集、复杂交通场景、MCU 端轻量 AI。现场测试可能提供十字路口、车道线、红绿灯、导航及其他道路场景，要求交付硬件、源码、文档和 3 分钟内 1080P 演示视频。

### 选题四：基于紫光同创 SoPC 的创新应用开发

开放命题，可在推荐 SoPC 平台上完成 AI 识别、图像处理或其他创新应用，按创新性、趣味性和实用性综合评价。

## 4. 为什么建议你先选 CPU 方向

你的已知起点是学过 Verilog、准备重做 24ysyx E2。E2 的公开课程目标正是从 Logisim 的“电路思维”切换到 HDL，覆盖 Verilog 基础、组合逻辑、时序逻辑和状态机。这些能力可以直接进入 RV32I CPU 赛题。

CPU 方向还具有三个优势：

1. 每个阶段都能用确定的指令测试验证，错误边界清楚；
2. 基础任务、CoreMark 和高阶优化形成连续路线；
3. 即使最后换题，流水线、RAM、总线、UART、CDC、时序约束仍然通用。

风险也很明确：Cache、异常中断、编译器工具链和时序优化会拉长周期。前期必须守住“先正确，再提速”的顺序。

## 5. 从新手到参赛版本的路线

### 阶段 A：E2 复习（1-2 周）

- 完成 HDLBits 指定的组合逻辑、触发器、计数器、移位寄存器和 FSM；
- 熟悉 `always_comb`、`always_ff`、阻塞/非阻塞赋值；
- 会写自检 testbench，会看波形；
- 完成本工程 ALU、立即数生成器和寄存器堆练习。

验收：不看参考代码能写出 ALU、计数器、FSM，并让单元测试全过。

### 阶段 B：RV32I 单周期基线（1-2 周）

- 理解六种指令格式和内存访问；
- 用指令测试逐条验证 RV32I；
- 跑通启动汇编和最小 C 程序；
- 接通 UART/GPIO。

验收：软件能通过 UART 打印、控制 LED；非法指令能被识别。

### 阶段 C：三段流水与上板（2-3 周）

- 实现 valid/stall/flush；
- 实现数据前递和 load-use 处理；
- 在 PDS 中完成综合、布局布线和引脚约束；
- 用 ILA 抓取 PC、指令、stall、branch_taken 和 commit。

验收：仿真回归通过，上板稳定运行，时序报告无违例。

### 阶段 D：CoreMark 与性能基线（2 周）

- 增加周期计数器和足够的 RAM；
- 移植 CoreMark，测试至少 10 秒；
- 记录主频、CoreMark、CoreMark/MHz、LUT、寄存器、BRAM；
- 通过波形找出 CPI 损失来源。

验收：结果可重复，有编译参数、运行日志和资源/时序报告。

### 阶段 E：高阶优化（4 周以上）

推荐顺序：I-Cache -> D-Cache -> 两路组相联 -> CSR/异常中断 -> BTB -> 应用或 AI 加速。每加入一项，都要有“功能回归 + 性能对比 + 资源代价”。

## 6. 作品交付清单

- 可综合的 Verilog/SystemVerilog 源码；
- PDS 工程、IP 配置、引脚与时序约束；
- 裸机软件、链接脚本、构建命令和二进制生成方式；
- 指令测试、模块测试、SoC 集成测试与波形；
- CoreMark 原始输出及运行时间；
- 最高频率、worst slack、LUT/FF/BRAM/DSP 报告；
- 系统架构图、流水线图、地址映射和接口时序；
- ILA 分析、性能瓶颈、优化前后对比；
- 可现场演示的开发板实物；
- 演示脚本、故障恢复步骤和备份镜像。

## 7. 现在要避免的坑

- 一开始就做 DDR3、PCIe 或双路 Cache，导致基础核长期不能运行；
- 只写 RTL，不写自动判定结果的 testbench；
- 把 `for` 循环当软件循环，不考虑综合出的并行硬件；
- 组合逻辑赋值不完整，产生锁存器；
- 多个时序块驱动同一寄存器；
- 用逻辑分频产生新时钟，却没有做时钟约束与 CDC；
- 只报告“能跑”，没有原始测试、主频、资源和复现步骤；
- 过早追求主频，在功能错误的 CPU 上做优化。
