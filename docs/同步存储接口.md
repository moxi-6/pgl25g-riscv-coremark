# 同步存储接口与 CPU 时序

2026-10-19：SoC 默认使用同步指令 ROM、同步数据 RAM。地址容量及 GPIO/UART 地址保持不变。这里定义的是 RTL 接口与仿真行为，块 RAM 的实际推断和固件初始化仍需通过 PDS 综合确认。

## 指令接口

| 信号 | 方向（相对 CPU） | 含义 |
|---|---|---|
| `imem_valid_o` | 输出 | 正在提出一个取指请求 |
| `imem_addr_o` | 输出 | 请求的字节地址，32 位对齐 |
| `imem_ready_i` | 输入 | 本拍可接受请求；仅 `valid && ready` 时接收 |
| `imem_rvalid_i` | 输入 | 已接收请求的返回数据有效 |
| `imem_rdata_i` | 输入 | 返回的 32 位指令 |

CPU 最多保留一个未返回请求，另有一个返回缓存槽。请求一旦提出，在 `ready` 为低期间必须保持 valid 和地址稳定，包括发生跳转或停机时。存储器对每个已接收请求恰好返回一次，返回不得早于接收后的下一周期；没有返回端反压。CPU 不会在没有预留返回空间时提出新请求。

`sync_imem` 可每拍接受一个请求：在接收沿注册数据，随后一周期 `rvalid` 为高，CPU 在下个上升沿接收该数据。内存读数据寄存器不带复位；只有有效位复位。地址越界或不对齐时返回全零非法指令，避免高位截断后读到别名地址。ROM 未载入区域默认填 EBREAK。

同一 ROM 现增加独立的同步数据读口，映射到数据地址 `0x20000000–0x20003fff`（默认 16 KiB）。该端口采用数据总线的完成握手，允许取指和数据读取在同一时钟沿访问不同字；写入不修改 ROM。其读数据寄存器同样不带复位。PDS 是否推断为双读口块 RAM 或复制 ROM，需检查实际综合报告。

执行级等待数据存储器时，取指返回可留在缓存，不覆盖 EX。分支/JAL/JALR 生效后，清除旧缓存；如果旧路径请求已提出或已接收，先保持请求并丢弃其返回，再取目标地址。EBREAK/非法指令/未对齐访问停机后不再产生新请求；原有请求仍可能完成并被丢弃。

`ASYNC_IMEM=1` 仅用于原组合 ROM 基线测试，忽略指令 ready/rvalid；正式 SoC 使用默认同步模式。旧 `simple_imem.sv` 不在板级 CPU 源文件清单中。

## 数据接口

原有 `valid/write/addr/wdata/wstrb/rdata/ready` 接口继续使用**完成握手**：CPU 必须保持请求和载荷稳定，直到上升沿采到 `valid && ready`。它与上面的指令“请求接收 + 独立返回”协议不同，不要混接。

`sync_dmem` 第一个等待周期的上升沿执行一次读/写，注册读数据并拉高 ready；CPU 在下个上升沿确认完成。完成沿不重复执行写操作，下一笔事务最早在随后周期开始。写支持四个独立字节使能，读采用旧数据语义。数组及读数据寄存器无异步复位，以便综合工具推断同步 RAM。

GPIO 仍立即完成；只有低字节使能时更新低 8 位。UART 低字节写入会等待发送器空闲，且恰好发送一个字节；UART 高字节写入完成但不发送。读 UART 返回 bit0=ready。未映射数据地址沿用原行为：读零、写入忽略、立即完成，当前没有总线错误异常。

## 复位、停机和软件限制

CPU 与两个存储器适配器必须共用复位，复位会取消未完成的取指返回及数据完成标志。RAM 内容不清空，已经在时钟沿发生的写入不会因复位撤销。启动代码仍负责清零 `.bss`。如果以后接入不能取消响应的跨时钟/外部总线，需要额外的事务标识或复位排空机制，不能只复位 CPU。

后续固件制作已更新链接布局并重新编译：`.rodata` 与带初值数据放入 RAM，ROM 保存其初值，启动代码通过 ROM 数据映射复制并清零 `.bss`，复位后重新初始化。具体构建命令、容量和软件边界见 `../software/README.md`。当前停机/非法访问检测仍不等同于完整异常、中断和 CSR 实现。

当前前端采用单请求与单缓存，优先保证等待、跳转和复位正确；不能宣称每周期提交一条指令。后续性能优化须以提交轨迹和实际 PDS 时序为依据。

## 已执行验证

- `tb_core`：保留原组合 ROM 基线，10 cycles / 7 commits。
- `tb_core_wait`：紧邻指令的 WB 前递遇到 5 周期数据等待，保持地址/数据/字节使能稳定，无重复提交，20 cycles / 7 commits。
- `tb_sync_memory`：同步 ROM 连续请求、时钟沿前保持输出、非二次幂边界、非法高地址不别名、RAM 四个字节使能、复位清除返回但保留内容。
- `tb_core_sync`：三种取指时序模式，逐条比对 28 次提交的 PC/指令；覆盖取指反压、多周期数据等待、缓存停等、LB/LBU/LH/LHU/LW、SB/SH/SW、load-use、BEQ/BNE、循环、JAL/JALR、FENCE。每次恰好 5 次读、3 次写、7 次旧路径返回丢弃。另检查 4 类故障停机无写入副作用、取指返回等待中复位。
- `tb_soc_memory`：真实同步 ROM/RAM 和 MMIO 集成；高字节 UART/GPIO 写不产生低字节副作用，错误路径 UART/GPIO 写不执行，UART 忙时等待，实际 TX 引脚只输出两个 Z。
- 原有 SoC 固件测试及 CPU 实板顶层串口解码测试继续通过；这是功能仿真，不是完整指令一致性验证或实板结果。
- 后续新增 `tb_runtime`：RAM 预置非零脏值，验证新编译 C 固件的字符串、初值及 BSS；程序主动破坏变量后再次复位，两次均输出 `RUNTIME OK`。完整回归现为 10 项。
