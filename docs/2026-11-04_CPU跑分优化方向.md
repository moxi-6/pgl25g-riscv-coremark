# CPU 跑分优化：热点、时序与实施顺序

2026-11-04。当前任务以 CPU/CoreMark 为主，应用开发暂缓。本轮完成方向复核、热点补测和 R3 布局布线时序测量；尚未实现乘法扩展，也没有新增实板成绩。

**建议优先实现可配置的标准乘法扩展，其次切分执行/访存长路径，再优化剩余访存和预测损失。** 保留 RV32I 配置作为对照。选择流水级数的依据是实际吞吐、CoreMark/MHz 和资源，而非级数本身。

## 1. 同一固件的实测对照

以下均为单次迭代、同一仿真固件、CRC 通过；退休指令均为 870,108。CoreMark/MHz 是单迭代周期推算，不能作为正式板上分数。

| 配置 | 每轮周期 | CPI | 推算 CoreMark/MHz | 50 MHz 布线后 WNS | 工具估算 Fmax |
|---|---:|---:|---:|---:|---:|
| 已验收取指重叠基线 | 2,102,202 | 2.41602 | 0.47569 | 本轮未重测 | 本轮未重测 |
| R1：连续同步取指 | 1,180,925 | 1.35722 | 0.84679 | 未测 | 未测 |
| R2：三段 + 16 项 BTB | 993,871 | 1.14224 | 1.00617 | +1.435 ns | 53.8648 MHz |
| R3：再分离译码级 | 1,021,006 | 1.17342 | 0.97943 | +2.521 ns | 57.2115 MHz |

R3 多出 27,135 周期，正好等于预测错误后的重定向次数，即每次增加一拍惩罚。固定 50 MHz 时，耗时增加 2.73%、吞吐下降 2.66%。其实际运行频率必须比 R2 高超过 2.73% 才能抵消。

若分别套用工具估算的 Fmax，R3 吞吐比 R2 高约 3.39%。这说明它可以保留作为提频候选，但工具估算不能代替目标频率重新约束、PLL 配置、时序验证和上板测量。提高频率本身也不会提高 CoreMark/MHz。

R2、R3 既有 9 项快速回归和 48 次 ISA 差分记录均通过；本轮又用 R2 快照重跑热点仿真，原有全部指标与之前逐项一致，计时区间与固件 ticks 一致，CRC 通过。

## 2. 最大热点是软件乘法

新增计数针对当前镜像中 `__mulsi3` 的符号范围，覆盖 CoreMark 的准确计时区间：

| 指标 | R2 实测 |
|---|---:|
| 软件乘法调用次数 | 9,396 |
| 软件乘法函数内退休指令 | 544,552，占总指令 62.58% |
| 每次调用的函数内指令数 | 平均 57.96 条，另有调用端开销 |
| 函数内 EX 占用周期 | 544,552，占总周期 54.79% |
| 函数内发生的重定向 | 15,269，占全部重定向 56.27% |

**62.58% 是指令占比，不是时间占比。** 现有乘法用移位、加法和循环实现，反汇编每位循环执行 7 条指令。消除软乘还会改变分支和调用分布，因此做完乘法后应重新分析热点。

资源具备实验空间：

| 资源 | R2 | R3 | 器件总量 |
|---|---:|---:|---:|
| LUT | 2,265 | 2,284 | 22,560 |
| 寄存器 | 1,515 | 1,646 | 33,840 |
| DRM18K | 16 | 16 | 60 |
| APM/DSP | 0 | 0 | 40 |

优先实验 `RV32I_Zmmul`，完整实现 `MUL/MULH/MULHSU/MULHU`，比较 DSP 映射和 2–3 周期的实现。只实现 MUL 时不能声称完整 Zmmul，更不能把缺少除法的配置标成 RV32IM。当前数据没有显示优先投入除法器的理由。

必须同步修改译码、暂停/前递、扩展指令差分检查、编译目标、固件校验器及报告里的 ISA/编译选项；当前 `verify_firmware.py` 仍只允许 RV32I。重点验证高半乘法的符号组合、零寄存器、背靠背依赖、等待与重定向。是否获得显著提升，以新固件的完整 CRC、周期、时序和资源为准，此处不承诺具体新分数。

若最终测试限定纯 RV32I，保留硬件基线，另测通用编译器运行库的乘法实现。该结果属于软件优化，应与同固件硬件改动分开记录。

## 3. 剩余 CPI 优化空间

当前 R2 的实测计数恰好满足：

```text
993,871 周期 = 870,108 退休指令 + 54,270 EX 空泡 + 69,493 访存等待
54,270 EX 空泡 = 2 × 27,135 次重定向
```

对这条固定指令流、单发射、保持频率不变：

| 理想化变化 | 吞吐提升上限 |
|---|---:|
| 全部停顿都消除，CPI 达到 1 | +14.22% |
| 仅消除全部重定向空泡 | +5.78% |
| 仅消除全部访存等待 | +7.52% |

这些是独立的乐观上限，不能相加，也不能套用到乘法扩展后的新指令流。

重定向分类：条件分支 17,546 次，JAL 1,208 次，JALR 8,381 次。JALR 包含调用、返回和间接跳转，不能将它们全归为返回预测失败。后续先补充 BTB 未命中/方向/目标错误分类，再决定扩大 BTB、调整索引或增加返回地址栈。

## 4. 流水线应切在哪里

R2 最差路径为：寄存器编号 → 寄存器堆读取/旁路 → ALU → 数据地址 → SoC 地址译码/ready → ex_wait → redirect → 流水寄存器使能，18 级逻辑，路由占约 69.8%。

R3 最差路径变为：寄存器编号/旁路 → ALU → 数据地址 → SoC 读数据选择 → WB 数据，17 级逻辑，路由占约 71.6%。虽然时序有所改善，但拆译码级仍将读取操作数、计算地址和访存选择留在同一条组合路径。

下一轮时序改动按成本递增试验：

1. 独立地址加法器与地址预译码，减少通用 ALU 和大型读数据选择器串联，核实综合结果是否真正缩短路径。
2. 请求/响应控制解耦，缩短数据地址经过 ready 回到流水控制的链路。
3. 依据报告试验 ID 读取寄存器、EX 计算/分支、MEM 访问、WB 写回的划分，配套前递和 load-use 停顿。不能假定五级必然胜过三级。

当前 RAM 协议每次操作下一拍才完成，EX 因而停住。可以先评估 store 接受即完成，再独立 MEM；必须保持 MMIO 顺序、字节写入和副作用只发生一次。数据旁路、访存吞吐、总线时序要一起检查。

目前程序及数据已在片内 RAM，正常顺序取指能逐拍供给；没有证据支持优先通过 Cache 提升当前跑分。Cache 如有赛题功能价值，可另立任务，暂不作为本轮主要提分方向。

## 5. 实施与验收顺序

1. **硬件乘法实验**：保留 RV32I 配置，对照完整 Zmmul，记录指令数、乘法等待、CRC、CoreMark/MHz、LUT/FF/DSP。
2. **重新分析热点并切分长路径**：先看乘法后的 profile，再选流水和访存改动；各改动单独比较。
3. **小成本编译扫描**：独立比较 O2/O3/Os、链接 relaxation，再考虑 LTO。当前关闭 relaxation，近距离调用仍常为 AUIPC+JALR；ROM 约 13,048/16,384 字节，需检查容量。LTO 可能移除 profiler 依赖的函数符号，应先调整计时定位方式。
4. **预测微调**：按新热点决定 BTB 16/32/64 和返回地址栈，而非先扩表。
5. **实板验收**：PLL、约束、CLOCK_HZ、UART 分频、计时解析保持一致；性能/验证种子 CRC 通过，保留原始串口 ticks，正式计分运行至少 10 秒。上游核心算法保持原样，软件、ISA、频率变化分别标注。
