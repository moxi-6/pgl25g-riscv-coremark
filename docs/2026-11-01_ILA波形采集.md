# 2026-11-01 硬件 ILA 波形采集（CoreMark 运行时）

## 结论

CPU 在实板运行 CoreMark 时，片上逻辑分析仪（ILA）成功采集 512 个采样点、92 路信号，
解码得到 149 次提交（commit）、150 次取指接收（fetch_take）、17 个不同 PC。
采样窗口落在 CoreMark 的 `matrix_mul_matrix_bitextract` 用例内部，并完整抓到它调用
软件乘法 `__mulsi3` 的 20 轮内循环。

这不是仿真数据，也不是外接逻辑分析仪：波形来自我们在 PGL25G 内实例化的 Debug Core，
通过 JTAG 读取，证据文件见下。

## 触发与采集

- 触发条件：`commit_valid` 上升沿（CoreMark 第一条提交即触发）。
- 采样时钟：`nt_sys_clk`（50 MHz）。
- 流程脚本：`scripts/run_coremark_ila_capture.ps1`
  1. 启动 `cdt_js.exe` 调试服务（127.0.0.1:65420）；
  2. `cdt_cfg_shell.exe` 下载 `atk_l50_top.sbit` + `atk_l50_top.smsk`（1 MHz，Shutdown 模式），回读校验 GOUTEN；
  3. `cdt_internal_capture` 按 FIC 配置触发、采样 512 点、导出 `.wdf`；
  4. `verify_coremark_ila.py` 解码 `.wdf`，写 `capture_result.json` 与 `coremark_ila_samples.csv`。

## 解码结果与解读

```
sample_count               512
channels                    92
commit_valid_samples       149
fetch_take_samples         150
unique_commit_pcs           17
commit_pc_min          0x00001668
commit_pc_max          0x00002c50
dmem_access_samples          0
cycle_counter_advances_every_sample   true
retire_counter_monotonic             true
core_was_running                     true
```

PC 分布（来自 `coremark_ila_samples.csv`）：

- `0x1668`–`0x167c`：`matrix_mul_matrix_bitextract` 中调用乘法后的一段（`0x1664` 为 `jalr __mulsi3`）；
- `0x2c28`–`0x2c50`：`__mulsi3` 函数体，32 位移位加法乘法循环，每个地址各出现 19–20 次。

也就是说：**采样窗口清晰记录了 CoreMark 核心用例正在执行，并完整捕捉到一次软件乘法的 20 轮迭代**。
`commit_valid` 149/512 ≈ 29%，与 3 级流水线在 50 MHz 下每 3–4 个周期提交一条指令的预期一致；
`dmem_access_samples = 0` 是因为该窗口恰好处在乘法循环内，没有访存指令。

## 局限与后续

- 单个窗口只覆盖 512 个周期（约 10 µs），要覆盖整条 CoreMark 需要多次触发或更大深度；
- 本次未采到访存信号，如需访存时序证据，应把触发条件改为 `dmem_valid`；
- 该 ILA 位流只用于取证，与发布版 `cpu/coremark` 位流是两份不同的工程，互不影响。
