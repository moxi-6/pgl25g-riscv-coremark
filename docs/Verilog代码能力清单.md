# Verilog/SystemVerilog 代码能力清单

这份清单按“能写出本赛题的 RV32I CPU”倒推。你可以把自己当作第一次学习：每一项都要达到“能解释、能手写、能用波形定位错误”。

## 1. E2 复习：先建立电路思维

24ysyx E2 的核心提醒是：数字电路设计主要做两件事——**实例化**和**连线**。HDL 不是按顺序执行的软件；代码描述的是并行存在的硬件。

### 必会语法

- `module`、端口方向、位宽、参数 `parameter`
- `logic`、常量位宽，例如 `32'h0000_0013`
- 连续赋值 `assign`
- `always_comb` 与阻塞赋值 `=`
- `always_ff @(posedge clk)` 与非阻塞赋值 `<=`
- `if/case/for`，以及完整默认赋值
- 模块例化、按名称连接端口
- 位选择、切片、拼接、复制、符号扩展
- 算术、比较、逻辑、移位和归约运算

### 必会电路

- 与或非、译码器、编码器、多路选择器
- 加法器、比较器、移位器
- D 触发器、寄存器、计数器、移位寄存器
- 同步复位、异步复位的差别
- Moore/Mealy 状态机
- RAM/ROM 的同步读、异步读和字节写使能

### 过关标准

- 能说明为什么组合逻辑不能遗漏赋值，否则可能推断锁存器；
- 能说明时序逻辑为什么使用 `<=`；
- 能从波形中找到“早一拍/晚一拍”的错误；
- 能完成 HDLBits 的组合逻辑、触发器、计数器、移位寄存器与 FSM 章节。

## 2. 工程仿真能力

比赛代码不能靠“下载到板子上试一试”来调。

- 会写时钟和复位激励；
- 会写自检断言：结果不符就 `$fatal`；
- 会构造边界输入：0、全 1、最大正数、最小负数、未对齐地址；
- 会读 VCD/波形，按“输入 -> 组合结果 -> 寄存器更新”追踪；
- 每个模块先单元测试，再做 CPU/SoC 集成测试；
- 固定随机种子并保存失败用例，避免不可复现。

本工程先运行 `tb_alu.sv`，再运行 `tb_core.sv`。当你修改 CPU 时，必须保证旧测试仍通过。

## 3. RV32I CPU 代码能力

### 指令与数据通路

- 看懂 R/I/S/B/U/J 六种立即数编码；
- 按 opcode、funct3、funct7 译码；
- 写 ALU、寄存器堆、立即数生成器；
- 算出分支/JAL/JALR 目标地址；
- 实现 LB/LH/LW/LBU/LHU 和 SB/SH/SW 的字节选通；
- 保证 `x0` 永远为 0。

### 三段流水

本框架采用教学用三段节拍：

```text
IF 取指  ->  EX 译码/执行/访存  ->  WB 写回
```

你需要掌握：

- 流水寄存器保存 `valid/pc/instr`；
- 数据相关通过写回前递解决；
- 数据存储器未 `ready` 时冻结 PC 和 EX；
- 分支或跳转成立时冲刷流水线中的错误路径指令；
- 非法指令和未对齐访问进入停止/异常路径；
- 用 `commit_valid/commit_pc/commit_instr` 观察退休指令。

### 从基础任务到高阶任务

1. 先让 RV32I 指令测试通过；
2. 加机器定时器和最小 CSR；
3. 加异常/中断入口、`mepc/mcause/mtvec/mstatus` 与 `mret`；
4. 接入 UART、GPIO，运行裸机 C；
5. 移植 CoreMark，建立周期计数；
6. 分开实现 I-Cache 和 D-Cache，再做两路组相联；
7. 加 BTB/方向预测器并统计命中率；
8. 用 PDS 报告优化主频、LUT 和时序路径。

## 4. FPGA 工程能力

- 能建立 PDS 工程、选器件、添加源文件、设置顶层；
- 能生成 PLL、片上 RAM 和 ILA 等厂商 IP；
- 能写主时钟约束，读懂 setup/hold 与 worst slack；
- 能按原理图填写时钟、复位、LED、UART 引脚；
- 能区分仿真模型和可综合代码；
- 能识别并处理跨时钟域：同步器、握手或异步 FIFO；
- 能查看 LUT、寄存器、BRAM、DSP 使用率；
- 能保存可复现的 PDS 版本、器件型号和构建步骤。

## 5. C 与软硬件协同能力

比赛基础任务需要 UART/GPIO，高阶任务使用 CoreMark，因此还要会：

- `riscv32-unknown-elf-gcc` 的 `-march=rv32i -mabi=ilp32`；
- 启动代码设置栈并调用 `main`；
- 链接脚本安排 `.text/.rodata/.data/.bss`；
- `volatile` 内存映射 IO；
- `objdump` 对照机器码、汇编和 PC；
- 使用 map 文件检查 ROM/RAM 占用；
- 设计周期计数器并确保 CoreMark 单次运行至少 10 秒。

## 6. 代码规范

- 一个模块只承担一类职责；
- 端口使用 `_i/_o` 后缀，低有效信号使用 `_n`；
- 时序块只更新寄存器，组合块先写默认值；
- 常量写清位宽，避免隐式符号扩展；
- 状态寄存器和 next-state 逻辑分开；
- 注释解释接口、时序与取舍，不逐行翻译代码；
- 提交前执行仿真、综合、时序检查，并保存结果。

## 7. 你的第一轮练习任务

1. 不看答案，重写一个 4 选 1 多路器、32 位加法器和带使能计数器；
2. 给 ALU 增加 50 组随机测试；
3. 手算 `addi x1,x0,5` 的机器码，再与 `objdump` 对比；
4. 在波形里标出 `addi -> add -> sw -> lw -> beq` 的每个流水阶段；
5. 故意删除前递逻辑，观察 `tb_core` 为什么失败；
6. 把数据存储器 `ready` 随机拉低，验证流水线不会重复提交指令。
