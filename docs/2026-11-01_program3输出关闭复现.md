# 2026-11-01 program=3 输出关闭复现

**最终结果：下载流程已修复，CPU UART 已恢复并实测通过。** 本机 PDS 2022.2-SP4.2 / 本块 PGL25G 上，脚本原默认 Combined（program=3）能复现持续的 GOUTEN=0。用户断电重新上电后恢复；干净状态下采用 Shutdown（program=1）及显式 readback=1，GUI 与 CLI 均保持 GOUTEN=1。原 CPU perf_report 位流下载、回读通过，COM8 实收完整 179 字节性能报告。没有改 CPU RTL、位流或电压约束。

## 已证实的触发步骤

在用户确认流水灯已恢复、GUI 状态为 0x001ffca0 的基础上，保持同一个 GUI/JTAG 会话、同一份 flow_led.sbit、同样的约束与供电，依次测试：

| 修复后的正式脚本 CLI 下载原 CPU perf_report 并回读 | 0x001ffca0，原始读数一致 | 1 |

原位流：`C:/fpga/riscv_l50/flowled_fix/generate_bitstream/flow_led.sbit`，SHA256 `7AFAB84F5721840A35E77EEBD10ABD54AFDD3713BD207BB335BBDF3C86D27773`。本轮未改位流、RTL、约束或跳帽，未写 Flash/eFuse。

`program=3` 是项目下载脚本原默认 Combined 模式的参数。官方工具文档说明它同时设置关断重配和 ISC 配置两位。该步骤在本机 PDS/本板组合上，使原本正常输出的相同设计进入 GOUTEN=0 状态。因此，故障触发点已定位到显式 program=3 下载路径。还没有定位到厂商工具内部哪条指令导致状态未释放。已经证明：先断电清除该状态，再使用 program=1/readback=1，可在本板保持输出正常。不能推广为所有 Pango 器件均存在该问题。

原 GUI 成功 Program 约 1.4～1.5 秒，显式 program=3 本轮约 39.1 秒。耗时区别只是旁证，决定性证据是前后同一设计的状态变化。

## 修复与验收

用户已回复完成断电重新上电。恢复原 flow_led 后，按上表依次完成 GUI 非 ISC 下载、CLI 非 ISC 下载/校验/原始读取及 CPU UART 验收。

`scripts/program_sram.ps1` 默认方式改为 Shutdown；`scripts/program_sram.tcl` 显式设置 readback=1，VerifyOnly 也同样设置。默认拒绝 Combined/ISC，保留显式诊断 opt-out；GOUTEN=0 从原来的警告改为操作失败。解析取最后一次 DONE/GOUTEN，避免早期成功掩盖后续失败。删除“CLI 永远无法点亮 IO”的错误断言。临时 UART 诊断入口也改成默认 Shutdown。

PowerShell 语法检查、Combined 在硬件操作前被拒绝的保护检查通过。正式脚本使用原 perf_report CPU 发布包，下载 8.9 秒、回读 10.1 秒通过，最终高层状态和原始状态均为 0x001ffca0。COM8 从下载前开始监听，无需再按复位即收到：

```text
PERF REPORT
CLOCK_HZ=50000000 hex=0x0000000002faf080
ACC=577756280 hex=0x00000000226fdc78
CYCLES=79920 hex=0x0000000000013830
INSTRET=24597 hex=0x0000000000006015
PERF DONE
```

十进制与十六进制数值一致；ACC/CYCLES/INSTRET 与既有仿真一致。仿真为了 UART 加速配置为 1 MHz，实板 CLOCK_HZ 是固件配置寄存器的 50 MHz，不能据此宣称已独立测量时钟。该工作负载 CPI 约 3.249，不能作为 CoreMark 成绩。

当前 SRAM 为 CPU perf_report，SHA256 `72FD06506678F9A1ECA18CB8D086D7FB15FFBE9A00D7C8E71417C62EEE4002AF`。当前状态与证据见 `build/board_current_state.json` 和 `build/uart_capture/cpu_perf_recovered_20261101_01/`（program.log、program_result.json、capture.bin/txt、verification.json）。本轮未改 RTL，未重跑全部 RTL 回归；旧离线 ZIP 未重打包，后续打包应先重新离线验收，因为下载脚本已变化。
